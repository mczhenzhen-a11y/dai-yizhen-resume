## 实习经历

### 广西融水大苗山土特产有限公司（柳州运营中心） — 运营实习生

**周期**：2025.01 – 2025.02 　　 **角色**：实习生

- **需求收集与多方对接**：对接商家（客户）、仓储、物流、业务多方，收集真实业务需求并逐项对齐；在多方信息不一致时把卡点列成清单逐项找人推动，让订单不在中间环节卡死。
- **第一版方案（走偏）**：进场时按"运营助理"的理解做——被动等业务分配任务，跟单走过场。**第一周就卡住**：盯着的几个 SKU 库存和上线时间点完全对不上，问了一圈没人说得清哪个环节的责任。
- **调整方法**：从"按指令做事"切换到"按链路画图做事"——把「入驻 → 资质审核 → 上架 → 库存 → 履约 → 验收」的链路画出来，**每个节点对到具体人和具体时间窗**。卡点立刻浮出来：商家资质材料滞后、平台规则口径不清、仓储备货没纳入项目计划。
- **交付结果**：跟进采购项目从需求确认、库存核对、物流安排到业务协调的全过程，**198000 元订单按期交付**；独立核算项目收益 **25740 元，收益率 13%**，账目明细交付公司留存。
- **获取成果**：摸清了"商家—平台—履约"的 B 端业务链路，形成了"先画清链路、再逐节点推动"的工作方法。**这段经历让我对 B 端业务的体感，比任何产品文档都更真实**。

### 宠芯 — 宠物智能项圈配套 APP 产品设计

**周期**：2025.04 – 2025.06 　　 **角色**：独立完成

- **第一版方案（走偏）**：立项时把"健康监测"（体温 / 心率 / 呼吸 / 活动量）作为核心卖点。**小样本问卷回收后第一个问题就暴露**：宠物走失、独自在家焦虑、老龄宠物不会表达这类真实痛点没在第一版功能里。
- **调整方法**：把调研题目从"对功能感兴趣程度"改成"实际生活中最焦虑什么"——**前者评估产品，后者暴露需求**；扩发问卷到 230+ 份 / 有效 200 份，Excel + SQL 独立做数据清洗。
- **核心定位调整**：从"**健康监测 App**"转向"**宠物安全守护 App**"——走失定位 / 独自在家动态 / 老龄健康档案排前三，健康监测降为辅助。
- **方案与产出**：输出竞品对比 + PRD（含功能优先级与数据指标）+ 信息架构 + 交互流程 + 移动端高保真方案 + 视觉规范文档。
- **获取成果**：跑通"被数据打脸 → 换方法 → 重新定位 → 落地"的完整迭代闭环，产出 200 份问卷分析报告与产品 PRD。

### 基于亲子协同的肥胖儿童体重管理服务系统

**周期**：2026.03 – 2026.06 　　 **角色**：项目第一负责人（4–5 人组）

- **第一版方案（走偏）**：按主流方法做问卷——300 份家长问卷 + 100 份儿童问卷。**数据回收后第一个问题就卡住**：家长关心"长不高""肥胖风险"，孩子在意"同学嘲笑""体育课跑不动"，两份问卷根本对不上话。
- **调整方法**：换成**角色扮演 + 入户观察**——去 3 个家庭做半日观察（晚饭后、睡前、周末写作业），拿到真实场景而不是"被访者自己觉得的答案"。
- **真实洞察**：① 体重管理冲突大多发生在晚饭后到睡前这一小时；② 家长真正想要的不是"孩子减肥"，是"和孩子一起动起来"的相处场景。
- **方案与产出**：绘制服务蓝图定义用户触点与前后台业务流程、绘制商业模式画布验证变现逻辑；独立撰写 PRD；作为负责人协调组内分工，从初稿到终稿按期交付。
- **获取成果**：产出用户画像报告、竞品分析结论、PRD、服务蓝图与商业模式画布；完整历练从需求到方案再到推进交付的产品全流程。

### 全屋家居智能中控屏产品设计

**周期**：2025 学年 　　 **角色**：独立完成

- **第一版方案（走偏）**：想做一个能控 30+ 种智能家居设备的中控屏。**去 3 个真实家庭做用户研究时发现**：用户根本记不住 30 个入口，日常实际控制的只有 5–7 个设备，其余功能"装上去就用过一次"。
- **调整方法**："大而全"改"**小而准**"——场景从"全屋"缩到"**玄关**"（门锁 + 主灯 + 空调 + 扫地机 + 摄像头 + 智能音箱都在这儿）。
- **方案与产出**：完成房间调研与用户调研，对标市面中控产品做功能对比，把"全屋智能控制"拆成照明、环境感知、设备联动等具体功能场景；撰写 PRD（功能范围与优先级），完成造型渲染与 UI 界面设计，输出软硬件一体方案。
- **获取成果**：产出场景调研报告、竞品功能对比、产品 PRD 与软硬件一体方案；练出"把大需求拆成可执行功能清单"与"切入高密度场景 → 跑通 → 外溢"的产品思路。

### 中国城市虚拟交互系统设计 — AR 地铁导览服务

**周期**：2026.04 – 2026.06 　　 **角色**：第一负责人

- **第一版方案（走偏）**：想做 AR 实时路径叠加导航。**demo 阶段就暴露问题**：地铁站信号差、定位漂移，AR 箭头抖得没法看；乘客真正缺的不是箭头，是"我在哪、下趟车在哪、出口在哪"的结构化信息。
- **调整方法**：把 AR 用在它合适的场景——**地标文化导览**：扫站厅展板触发 AR 推送线路历史、换乘信息、出口推荐；保留"轻量 AR 换乘指引"作兜底。
- **方案与产出**：通过问卷和用户流程图把乘客碎片诉求拆成"换乘导航"与"文化导览"两个场景；对标同类出行产品划定 MVP 边界与优先级；用 Figma 完成信息架构、交互流程与高保真方案。
- **获取成果**：产出双场景功能框架、竞品分析与含 MVP 边界的 PRD；练出从模糊诉求里切出清晰产品范围、以及"主推 + 兜底"的架构思维。
