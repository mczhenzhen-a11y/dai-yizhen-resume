## 项目经历

### 居家远程办公人群人机工程学设计 — 升降桌（家居 / 办公家具方向）

**周期**：2025 学年 &nbsp;&nbsp; **角色**：产品设计师

- **第一版走偏**：按教科书的做法，套用 ISO 人机工程学标准（坐姿 / 站姿 / 桌面高度 / 视距）做设计。数据本身没错，但**居家办公和办公室白领的场景差异极大**——家里有小孩、有宠物、桌面常堆东西，教科书假设的"理想工作位"在真实家庭里根本不存在。
- **调整方法**：换成**"行为模式 + 健康风险"双线研究**——真实观察 5 个居家办公家庭 3 天，记录升降桌高度变化的实际次数；再调研"不站立"的真实原因（桌面太乱、起身没处放东西、被打断）。
- **设计策略调整**：从"**促用户站立**"转向"**降低站立阻力**"——方案里增加桌面收纳分区、起身常用物品固定位、起身动作引导刻度。不是逼用户站起来，是让站起来这件事没那么麻烦。
- **方案输出**：用 **Rhino 建模、KeyShot 渲染**输出升降桌人机工程学方案；独立撰写产品 PRD，明确功能范围与优先级。
- **获取成果**：产出行为与健康研究分析、竞品对比、产品 PRD 和升降桌设计方案；建立起"**数据真实 ≠ 场景真实**、家具要同时算清材料和结构"的产品意识。

### 全屋家居智能中控屏（智能家居方向）

**周期**：2025 学年 &nbsp;&nbsp; **角色**：独立完成

- **第一版走偏**：想做能控 30+ 种智能设备的中控屏，当所有家庭设备的"总指挥"。去 3 个真实家庭做用户研究时发现——**用户根本记不住 30 个入口**，日常实际控制的只有 5–7 个设备，其余功能"装上去就用过一次"。
- **调整方法**："大而全"改"**小而准**"——把场景从"全屋"收敛到"**玄关**"（家庭里被多设备密集触达的场景：门锁 + 主灯 + 空调 + 扫地机 + 摄像头 + 智能音箱都在这儿）。
- **方案输出**：撰写产品 PRD（功能范围与优先级）；完成产品造型渲染（KeyShot）和 UI 界面设计（Figma），输出软硬件一体方案。
- **获取成果**：产出场景调研报告、竞品功能对比、产品 PRD 和软硬件一体方案；练出了"**小而准 > 大而全**、切入高密度场景再外溢"的硬件产品思路。

### 康复握力圈产品设计（家用器具方向）

**周期**：2025 学年 &nbsp;&nbsp; **角色**：产品设计师

- **第一版走偏**：按"康复训练器械"思路做，参考医院康复科手部训练器——造型方正、配色医用白、握把带刻度，看起来很"专业"。
- **调整方法**：拿到 5 个康复期用户家里做研究，反馈高度一致——"**不想让家人看到这是医疗器械**""放在客厅像在医院"。器械感太强的产品，用户会把它收进抽屉，收进去就不用了。回到真实场景：用户要的不是"被提醒在康复"，是"**康复这件事不打断我的正常生活**"。
- **设计策略调整**：走"**去器械感**"路线——圆润外壳、家居配色（暖灰 / 燕麦 / 莫兰迪）、一体成型无刻度条，外观像家居摆件而非医院设备；功能（握力训练 / 计数）全部保留。
- **全流程交付**：完成调研 → **Rhino 建模 → KeyShot 渲染 → 展板排版**全流程。
- **获取成果**：产出用户研究结论 + 造型方案与渲染展板；验证了"**去器械感 / 去工具感**"是家用康复与家用健身类产品的核心设计策略，使用频次明显提升。

### 宠芯 — 宠物智能项圈配套 APP 产品设计（软硬一体 · 实体产品 + APP）

**周期**：2025.04 – 2025.06 &nbsp;&nbsp; **角色**：独立完成

- **第一版走偏**：立项时把"健康监测"（体温 / 心率 / 呼吸 / 活动量）当核心卖点——智能项圈听起来就该做这个。**小样本问卷回收后第一个问题就暴露**：宠物走失、独自在家焦虑、老龄宠物不会表达等真实痛点都没在第一版功能里。
- **调整方法**：把调研题目从"对功能感兴趣程度"改成"实际生活中最焦虑什么"——**前者评估产品，后者暴露需求**；扩发问卷到 **230+ 份 / 有效 200 份**，用 **Excel + SQL** 独立做数据清洗与统计。
- **核心定位调整**：从"健康监测 App"转向"**宠物安全守护 App**"——走失定位 / 独自在家动态 / 老龄健康档案排前三，健康监测降为辅助。
- **方案输出**：竞品调研 + 独立撰写 APP 产品 PRD（含功能优先级与数据指标）+ 信息架构 + 交互流程 + 移动端高保真方案 + 视觉规范文档。
- **获取成果**：跑通"**被数据打脸 → 换方法 → 重新定位 → 落地**"的完整迭代闭环；学会用数据决定产品取舍。

### 基于亲子协同的肥胖儿童体重管理服务系统（软硬一体 · 实体设备 + 平台）

**周期**：2026.03 – 2026.06 &nbsp;&nbsp; **角色**：项目第一负责人（4–5 人组）

- **第一版走偏**：先按主流方法做问卷——300 份家长 + 100 份儿童问卷。**数据回收后第一个问题就卡住**：家长关心"长不高""肥胖风险"，孩子在意"同学嘲笑""体育课跑不动"，两份问卷对不上话。
- **调整方法**：换成**角色扮演 + 入户观察**，去 3 个家庭做半日观察（晚饭后 / 睡前 / 周末写作业），拿到真实场景而非"被访者自己觉得的答案"。
- **关键洞察**：家庭体重管理冲突多发生在晚饭后到睡前；家长真正要的不是"孩子减肥"，是"**和孩子一起动起来**"的相处场景——这才是"亲子协同"切入点的真正来源。
- **方案输出**：独立撰写 PRD；绘制服务蓝图与商业模式画布；设计 Web 端服务平台（Figma）与居家教练随身设备（**Rhino + KeyShot**）；协调组内分工按期交付。
- **获取成果**：产出用户画像报告、竞品分析结论、PRD、服务蓝图、商业模式画布及软硬件一体方案；作为负责人完整历练了市场定位、需求分析与团队推进。
