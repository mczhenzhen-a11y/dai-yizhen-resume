## 二、业务与产品：他们到底做什么

### 核心赛道：数据安全流通（隐私合规管理）

把能力拆成三个版块：

| 版块 | 干什么 |
|------|------|
| **隐私安全评估** | 帮客户识别隐私数据的存储与流通风险，做合规评估 |
| **密态数据流通** | 在不暴露原始数据的前提下，让数据能共享、能流通、能交易 |
| **隐私态势感知** | 持续监测隐私数据的流转状态与风险态势 |

### 产品线：Data-Tunnel 系列

| 产品 | 中文 | 作用 |
|------|------|------|
| Data-Tunnel Inventory Analyze | **数据分类分级系统** | 自动识别、给数据打标分级（哪些是敏感数据） |
| Data-Tunnel Hetero Sync | **异构数据同步系统** | 不同数据库 / 系统之间安全搬运数据 |
| Data-Tunnel Static Masking | **静态数据脱敏系统** | 把存量数据里的敏感字段"打码" |
| Data-Tunnel Dynamic Masking | **动态数据脱敏系统** | 查询时实时脱敏，原始数据不外露 |
| Data-Tunnel Multi-Party Computing | **多方安全计算系统** | 多方联合计算但不互相看到对方原始数据 |

核心技术关键词：**协议解析、去标识化、自适应**。交付形态为**纯软件交付**（容器化，支持公有云 / 虚拟化 / X86 物理机），已与多家业务、安全、运维、数据库厂商做接口集成。

### 客户

**政府、银行、保险、证券、医疗、教育、物流** 等行业，含**世界 500 强**企业，累计数十家客户。典型场景：某 TOP500 公司用 airflow 调用凯馨服务做任务编排。

> **为什么这决定简历写法**：客户是**银行 / 保险 / 政企**——这类客户要的不是"好用"，而是"合规、安全、能通过审计、能写进招标文件"。所以你后面会看到 JD 要求交付"招标参数""产品白皮书"——**这就是 ToB 软件产品经理区别于 C 端 PM 的地方**：一半时间做产品，一半时间做**售前材料**（白皮书 / 彩页 / 胶片 / 招标参数），陪销售打单。

## 六、缺口与补救（按优先级）

### 🔴 缺 1：理工科背景（学位类型）

JD 第 1 条明确要"计算机 / 信息管理 / 电子信息工程**及其他理工科背景**"。工业设计的学科门类**因校而异**：
- 授**工学学士** → 直接命中，教育背景里大胆标；
- 授**艺术学学士** → 不主动提学科门类，改写为"**工科训练背景**"（Rhino 三维建模 / 人机工程 / 结构工艺 / 数据调研），用能力证明理工底色。

**动作**：查一下学位证上写的是"工学学士"还是"艺术学学士"，告诉我，改一处标注即可。

### 🟡 缺 2：墨刀 / ProcessOn

JD 明文要这三个工具，XMind 你已掌握。墨刀（原型）和 ProcessOn（流程图 / 思维导图）都与 Figma / XMind 操作逻辑同源，**各花半天就能上手**。
**动作**：投递前用墨刀画一遍宠芯 APP 的 3–5 个核心页面，简历就能从"正在上手"升级成"已上手"。同时把 ProcessOn 画一张**宠芯功能架构图**当作练习。

### 🟡 缺 3：数据安全 / 隐私合规行业认知

这是**领域知识缺口**，对应届生不是硬伤，但面试一定会问"你怎么理解数据安全 / 数据流通"。
**必背 5 个概念**（半天搞懂即可）：
1. **数据分类分级**——先给数据打标（哪些是敏感数据），是一切安全的前提
2. **数据脱敏**——静态（存量打码）vs 动态（查询时实时打码）
3. **去标识化 / 匿名化**——去掉能指向个人的特征
4. **隐私计算 / 多方安全计算**——多方一起算，但互相看不到原始数据
5. **政策背景**：《数据安全法》《个人信息保护法》落地 + **数据要素市场化**（数据能交易了）

### 🟢 缺 4：招标参数 / ToB 售前物料

应届生普遍没有，不用慌。用"**结构化文档输出能力 + 设计背景**"承接即可，面试讲"我知道 ToB 产品经理要陪销售打单，白皮书和彩页要既能讲清技术、又能让客户爽快地签字"。

## 七、面试高频追问预备

**Q1｜"你是工业设计背景，为什么想做 B 端产品经理？"**
> 我在融水实习时做的其实是 B 端的事：帮商家把产品上到 832 平台、核对资质、跟进订单从需求到交付。我发现 B 端产品跟 C 端不一样——用户是一个个具体的客户，需求要一条条对齐，交付要落到文档和流程上。我做过 5 份 PRD，也习惯把需求写成开发能直接用的东西，这正是我想往 B 端走的原因。凯馨做的是数据安全流通，客户是银行和政府，这种"把复杂业务讲清楚、写进文档"的能力正好用得上。

**Q2｜"你没有软件 / 数据安全行业经验，怎么快速上手？"**
> 两点。第一，我知道这个行业的底子是政策驱动的——《数据安全法》《个人信息保护法》落地后，数据分类分级、脱敏、隐私计算成了刚需，我这两天已经把数据分类分级、静态/动态脱敏、多方安全计算这几个概念过了一遍。第二，我上手新东西有方法——从工业设计自己学 SQL、学服务设计、拆解 10+ 家公司产品岗 JD，都是自驱完成的。

**Q3｜"写产品白皮书、彩页、胶片这类售前材料，你有经验吗？"**
> 直接经验没有，但我有相近的底子。5 份 PRD 让我习惯把功能讲清楚；我有设计背景，PS、Illustrator、Figma 都能用，彩页这类"要好看又要清楚"的东西我不怵；项目的汇报 PPT 也一直是自己做。我知道 ToB 产品经理要陪销售打单，材料既要讲清技术，也要让客户看得懂、愿意签。

**Q4｜"你怎么理解交付流程？"**
> 我理解交付不只是把产品做出来，而是要跟客户项目的节奏走——要有实施文档、要盯进度、要提前预判延期风险。我在融水跟订单时就是这么做的：把每个环节的卡点列成清单，逐项找人推动，避免订单在中间环节卡死。功能延期预警本质上是同一件事，只是从订单变成了产品功能。

**Q5｜"为什么选我们这种 50 人的公司，不投大厂？"**
> 我看了贵公司的情况——交大团队、奇安投资领投、做数据安全流通。说实话，小团队对我更有吸引力：产品助理能真正碰到从调研到发布的完整流程，而不是在大厂里只负责一个模块。我也看到 JD 里写了"愿意往 B 端方向发展者优先"，我的方向本来就在这儿。
