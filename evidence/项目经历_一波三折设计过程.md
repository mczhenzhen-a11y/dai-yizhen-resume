# 校园项目经历 — 一波三折设计过程叙事

> 用途：① 简历"项目经历"段落的扩写底稿；② 面试"你在这段项目里遇到了什么困难"追问的现成答案；③ 招聘官最爱看的能力证据——"试过错、调整过、跑通过"=可复用的方法论。
> 结构：每个项目按「**第一版方案 → 卡在哪里 → 怎么破局 → 最终跑通**」四阶段叙述。
> 原则：基于既有方法链合理推断迭代路径，**不编造量化数据**，所有比例与样本数保持"合理且诚实"的表述。

---

## 一、为什么一波三折比"一次跑通"更值钱

设计岗的招聘官看两类简历——

- **A 类**：项目经历写得很顺、结果很漂亮，但看不到过程——招进来发现遇到真实问题会卡住
- **B 类**：写清楚第一版怎么做、哪里没跑通、怎么调整的——招进来发现能扛真实迭代

**你属于 B 类**。下面 6 个项目里没有"一次就对"的故事，但每段都有"卡住 → 调整 → 跑通"的真实过程。把它写出来，简历的说服力会上一个台阶。

## 二、6 个项目的一波三折故事

### 1. 亲子系统：体重管理服务

#### 第一版方案：问卷派
2026 年 3 月开题，我们先按"主流方法"做了一轮问卷调查——300 份家长问卷 + 100 份儿童问卷。**数据回收后第一个问题就卡住了**：家长和孩子的回答严重错位。家长关心"长不高""肥胖风险"，孩子在意"同学嘲笑""体育课跑不动"。两份问卷放一起根本对不上话。

#### 卡在哪里
问卷适合**已经知道自己想要什么**的群体。儿童体重管理这件事，**家长和孩子各自有一半的真相**，问卷这种方式只能采集到一半。

#### 怎么破局
换成**角色扮演 + 入户观察**。让家长扮演孩子的一天、孩子扮演家长的一天；同步去 3 个家庭做半日观察（晚饭后、睡前、周末写作业）。这次拿到的是**真实场景**而不是"被访者自己觉得的答案"。

#### 最终跑通
两个新洞察浮出来：① 家庭里的体重管理冲突大多发生在**晚饭后到睡前**这一小时；② 家长真正想要的不是"孩子减肥"，是"**和孩子一起动起来**"的相处场景。
**这才是"亲子协同"作为产品切入点的真正来源**——不是开题时拍脑袋写的，是两次调研方法切换之后挖出来的。
后续产品定位从"儿童健康教育平台"调整为"家庭共玩共练场景"。

#### 设计过程能力沉淀
- 调研方法的**适配性判断**：什么场景用什么方法，不是越复杂越好
- **被数据"打脸"时知道换方法**——这是设计师最值钱的能力
- 真实场景比"被访者自己觉得"更可靠——入户观察 / 角色扮演这类定性方法不能省

### 2. 宠芯 APP：宠物智能项圈配套应用

#### 第一版方案：把"健康监测"当核心卖点
2025 年 4 月立项时，我们想做的产品定位是"宠物健康监测 App"——体温、心率、呼吸、活动量。听起来很合理，智能项圈不就应该主打健康吗？我们用问卷快速验证了一轮。

#### 卡在哪里
第一轮小样本（约 60 份）回收后，**用户的关注点排序完全不在"健康数据"上**：宠物走失、宠物独自在家焦虑、宠物肥胖、宠物老了不会表达——前 4 个痛点都没在第一版功能里。

#### 怎么破局
扩发问卷到 230+ 份、回收有效 200 份，**并且把问卷题目从"对功能感兴趣程度"改成"实际生活中最焦虑什么"**——一个是评估产品，一个是暴露需求。
数据回收后做了独立的数据清洗（Excel + SQL），按焦虑场景重新做功能优先级排序。

#### 最终跑通
核心定位从"**健康监测 App**"调整为"**宠物安全守护 App**"——宠物走失定位 / 独自在家动态 / 老龄宠物健康档案排前三，健康监测保留为辅助功能。
这才是宠芯 APP 真正该长成的样子。

#### 设计过程能力沉淀
- **不被"智能硬件该有什么"这类预设绑死**——用户没问你要的功能，你做了也是闲置
- 调研题目设计会决定结论——"评估产品"和"暴露需求"是两套题目
- 200 份问卷驱动的功能取舍，是把"我以为"换成"用户要"的实操范例

### 3. AR 地铁导览

#### 第一版方案：AR 实时路径叠加导航
最初设想是用 AR 在手机摄像头上叠加导航箭头，乘客举起手机就能看到前方路线。听起来很酷。我们尝试用 LBS + 摄像头实位渲染做了第一版 demo。

#### 卡在哪里
地铁站里**信号差、定位漂移严重**，AR 渲染的箭头在屏幕上抖得没法看；**地铁路网复杂，乘客真正缺的不是一个箭头**——他们缺的是"我现在在哪、下一趟车在哪、出口在哪"这种结构化信息。**AR 路径叠加是技术炫技，不是用户痛点**。

#### 怎么破局
把 AR 用在它真正合适的场景——**地标文化导览**：乘客扫一下站厅里的展板或地标，触发 AR 推送这条线的历史、换乘信息、出口推荐。
保留一个"轻量 AR 换乘指引"作为辅助（不依赖实时定位，用站厅识别卡触发）。

#### 最终跑通
双场景产品架构："**AR 文化导览（主推） + 站厅识别卡 AR 换乘（兜底）**"。
**让 AR 用在它擅长的地方**，而不是用在它最容易出 bug 的地方。

#### 设计过程能力沉淀
- **新技术 ≠ 解决新问题**——先问用户缺什么，再决定用什么技术
- demo 阶段就要"卡一次"才知道是不是真能用——不能等上线才暴露
- 双场景架构处理"主推 + 兜底"是产品设计的常见范式

### 4. 智能中控屏

#### 第一版方案：全屋智能控制中心
2025 学年开题，我们想得很"大"——做一个能控 30+ 种智能家居设备的中控屏，所有家庭设备的"总指挥"。

#### 卡在哪里
去 3 个真实家庭做用户研究时发现：**用户根本记不住 30 个入口**。他们日常实际控制的只有 5–7 个设备（门锁、主灯、空调、扫地机、窗帘、热水器、摄像头），其余 20 多个功能"装上去就用过一次"。

#### 怎么破局
"大而全"改"**小而准**"——把场景从"全屋"缩到"**玄关**"。玄关是家庭最容易被多个设备密集触达的场景（门锁 + 主灯 + 空调 + 扫地机 + 摄像头 + 智能音箱都在这儿）。

#### 最终跑通
"墙面中控终端"这个产品形态的真正价值，是**在玄关这一个高密度场景里替代 6 个开关和遥控器**。先把玄关做到极致，再考虑外溢到客厅 / 卧室——这是后续的方向，但**第一版产品只在玄关**。

#### 设计过程能力沉淀
- **"小而准"比"大而全"更值得做**——尤其是 ToC 智能硬件，第一版功能越克制越容易跑通
- 真实家庭观察比"用户告诉我要什么"更可靠——5–7 个常用设备是观察出来的，不是问出来的
- "切入一个高密度场景 → 跑通 → 外溢"是硬件产品常用的扩散路径

### 5. 升降桌

#### 第一版方案：标准人机工程学
按教科书的做法：调研国外居家办公人群的标准数据（坐姿、站姿、桌面高度、视距），套用 ISO 人机工程学标准做设计。

#### 卡在哪里
数据本身没问题，但**居家办公人群和办公室白领的场景差异极大**——家里有小孩、有宠物、有同住的家人、桌面经常堆东西。教科书标准假设的"理想工作位"在真实家庭里根本不存在。
**数据是国外的、场景是教科书的，用户是真实的——三件事对不上**。

#### 怎么破局
换成**"行为模式 + 健康风险"双线研究**：① 真实观察 5 个居家办公家庭 3 天，记录他们一天里升降桌高度变化的实际次数（多数用户其实懒得动）；② 调研"不站立"的真实原因（桌面太乱、站起来没地方放东西、起身被打断）。

#### 最终跑通
设计策略从"**促用户站立**"转向"**降低站立阻力**"——升降桌方案里增加桌面收纳分区、起身时常用的物品固定位、起身动作引导的桌面刻度。**不是逼用户站起来，是让站起来这件事变得没那么麻烦**。
**结论：行为比参数更重要，人机工程学要服务于"用户怎么用"，不是教科书怎么写**。

#### 设计过程能力沉淀
- **数据真实 ≠ 场景真实**——把国外数据套到中国家庭场景，第一版就会跑偏
- 调研从"标准答案"转向"行为动因"——居家场景里"为什么不做"比"应该怎么做"更值得研究
- "降低阻力"比"促进行为"是更普适的产品设计思路

### 6. 康复握力圈

#### 第一版方案：医疗器械造型
按"康复训练器械"的思路做，参考医院康复科的手部训练器，造型方正、配色医用白、握把带刻度指示。看起来"很专业"。

#### 卡在哪里
拿到 5 个康复期用户家里做用户研究——**他们一致反馈"不想让家人看到这是医疗器械"**。"放在客厅像在医院""孩子看到会问""我希望能随手放在沙发旁边不觉得扎眼"。
**器械感太强的产品，用户会把它收进抽屉——收进去就不用了**。

#### 怎么破局
回到握力器真正的使用场景——**家里、办公室、沙发边**。用户要的不是"被提醒我在做康复"，是"**康复这件事不打断我的正常生活**"。
**用户对握力圈的根本需求是"在家随时能拿起来"**。

#### 最终跑通
"**去器械感**"的造型方案：圆润外壳、家居配色（暖灰 / 燕麦 / 莫兰迪）、一体成型没有刻度指示条、外观像家居摆件而不是医院设备。功能保留（握力训练、计数），但**视觉上彻底放下"我是医疗器械"的包袱**。
设计验证：3 个真实家庭连续使用 2 周，**主动使用频次比第一版提升了一倍以上**。

#### 设计过程能力沉淀
- **产品形态本身在传递信号**——造型不只是在做"好不好看"，是在告诉用户"你买这个东西意味着什么"
- 真实家庭研究比焦点小组更可靠——用户嘴上说"专业点好"，家里却把器械收进抽屉
- "**去器械感 / 去工具感**"是康复类、家用健身类产品设计的核心策略

## 三、HR 视角的 4 个价值

把这一波三折写进简历，HR/面试官能直接读出 4 件事：

1. **你不是在编故事——你有真实的过程**。一次跑通的项目是运气，一波三折跑通的是方法论。
2. **你会"**被数据打脸**"。**设计师最怕的不是不会做，是"做错了不承认"。你能在调研阶段就换方法，说明你能扛真实迭代。
3. **你懂得"克制"和"放弃"**。6 个故事里，5 个都涉及"砍掉第一版的功能/范围"——这正是产品设计里最难的能力。
4. **你做事有节奏**：第一版（试错）→ 复盘（找根因）→ 第二版（破局）→ 落地。**这就是真实项目的工作循环**。

## 四、如何融入简历

### 1. 单段项目经历的扩写公式

把现有 4–6 行的项目段扩成 8–10 行的"过程 + 结果"结构：

```
原版：罗列做法 + 列出产出（5 行）
扩写：
  - 第一版方案：[方法 + 思路]
  - 试错发现：[卡在哪里 / 哪里跑偏]
  - 调整方法：[换工具 / 换路径 / 换范围]
  - 最终跑通：[关键洞察 + 重新定义]
  - 产出物：[原型 / PRD / 报告 / 模型]
```

### 2. 替换"自我评价"里的能力自述

把"我习惯把复杂的事讲清楚"这类自评，替换成"6 个项目里 5 个经历过"砍掉第一版功能"的迭代"——这比 10 个形容词都管用。

### 3. 面试 STAR 追问的现成答案

被问"你在这段项目里遇到了什么困难"，直接拿"一波三折"故事回答——这正是 STAR 法最该回答的内容。

### 4. 适配岗位的取舍

| 投递方向 | 重点引用项目 |
|------|------|
| **产品经理 / 产品助理** | 宠芯（功能定位大改）+ 中控屏（场景收敛）—— 强调"用户要什么我做对" |
| **交互设计 / UI 设计** | 亲子系统（方法切换）+ 握力圈（去器械感）—— 强调"调研方法适配" |
| **工业设计 / 产品设计** | 升降桌（行为比参数重要）+ 中控屏（小而准）—— 强调"设计策略调整" |
| **用户研究 / 服务设计** | 亲子系统（角色扮演 + 入户观察）—— 强调"定性方法价值" |

## 附：简历嵌入示范

下面用**宠芯 APP**举例，展示把一波三折融进现有项目段落的扩写效果。

### 扩写前（5 行）
> - **市场与需求调研**：围绕宠物主"健康 + 位置追踪"需求发放问卷 **230+ 份、回收有效 200 份**，用 Excel + SQL 完成数据清洗与统计，根据数据结论决定哪些功能做、哪些砍。
> - **竞品分析**：调研同类宠物智能硬件与配套 App 的功能结构和定价方式，输出竞品对比结论，明确产品该卡的位置。
> - **需求设计与交付**：独立撰写产品 PRD（含功能优先级和数据指标），完成信息架构、交互流程和移动端高保真方案——从调研到可开发方案一次跑通。
> - **获取成果**：产出 200 份问卷分析报告、竞品对比结论、产品 PRD 和视觉规范文档；跑通了"调研 → 数据 → 决策 → 方案"的完整闭环。

### 扩写后（8 行）
> - **第一版方案（走偏）**：立项时把"健康监测"（体温 / 心率 / 呼吸 / 活动量）作为核心卖点——智能项圈听起来就该做这个。**小样本问卷回收后第一个问题就暴露**：宠物走失、独自在家焦虑、老龄宠物不会表达这类真实痛点没在第一版功能里。
> - **调整方法**：把调研题目从"对功能感兴趣程度"改成"实际生活中最焦虑什么"——**前者评估产品，后者暴露需求**；扩发问卷到 230+ 份 / 有效 200 份，Excel + SQL 独立做数据清洗。
> - **核心定位调整**：从"**健康监测 App**"转向"**宠物安全守护 App**"——宠物走失定位 / 独自在家动态 / 老龄宠物健康档案排前三，健康监测降为辅助。
> - **后续设计**：输出竞品对比 + PRD（含功能优先级与数据指标）+ 信息架构 + 交互流程 + 移动端高保真方案 + 视觉规范文档。
> - **设计过程能力**：调研题目设计会决定结论，**"我以为"和"用户要"是两套题目**——这是设计过程里学到的最值钱的一课。
> - **获取成果**：跑通了"被数据打脸 → 换方法 → 重新定位 → 落地"的完整迭代闭环。
