## 二、为什么这四项证据改变了简历的底层结构

### 变化 1：PRD 从"缺口"变成"硬证据"——这是最值钱的一项

在你之前的 JD 拆解报告里，**PRD 缺口出现在每一份 PM 岗位的待办清单第一条**：

- 倍思奇 IoT："投递前最高优先动作：补写 1 份简版 PRD"
- 信人智能："PRD / 竞品分析 —— **弱**"
- 通用 PM 校招 Y："最大缺口仍是 PRD"

现在这个缺口**全部消失**。而且它不是"补了一份"，而是**5 个项目都有**——这在应届生简历里属于稀缺项，直接解决了 JD 里最高频的两句话：
- 「负责产品需求文档的撰写」（通用 PM JD 职责第 2 条）
- 「协助完成产品需求文档（PRD）撰写」（倍思奇 JD 第 1 条）

### 变化 2：SQL 让"数据驱动"从形容词变成可验证能力

过去"数据驱动决策"这条在简历里只有 Excel 和问卷统计支撑，说服力有限。现在补上了 SQL：
- **写实场景**：用 Excel + SQL 完成 200 份问卷的数据清洗与统计（这是真实发生过的动作）
- **可展示物**：自建的投递岗位汇总数据库（岗位 / 公司 / JD 关键词 / 匹配度 / 状态 / 时间）——这是一个**面试官可以当场看的东西**，比"熟悉 SQL"四个字重得多

### 变化 3：竞品分析从"课程训练"改为"已完成 5 份"

原来的写法：
> 竞品对标（课程内训练）

现在的写法：
> 已完成 5 份竞品分析，习惯先做赛道对标再定功能取舍

差别在于：**前者是学习经历，后者是产出结果**。JD 里凡出现"竞品分析""竞品调研""竞品功能对标"（万辰 S、倍思奇、京东 T 都有），现在都直接命中。

### 统一处理原则

1. **PRD 结构统一表述**，便于面试官一眼识别你的文档规范：
   > 项目背景 → 目标用户与场景 → 竞品分析结论 → 需求列表与优先级（P0/P1/P2）→ 功能描述与业务流程 → 界面说明 → 数据指标与验收标准
2. **SQL 不空喊熟练**，一律绑定真实场景（问卷数据清洗 / 投递数据库 / 电商取数 / 交易对账），并注明 MySQL 范围
3. **不虚构数字**：竞品分析写"5 份"（对应 5 个项目），不编造"调研了 20 家竞品"这类无法证实的表述
4. **去掉失效标注**：所有【待本人补充：如会 SQL 请补充】已清除（已核验无残留）
