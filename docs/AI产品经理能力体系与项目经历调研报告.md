## 一、AI 产品经理是什么

AI 产品经理（AI PM）不是"会用 ChatGPT 的产品经理"，而是能够**驾驭不确定性、设计智能系统、平衡业务与技术边界**的"智能架构师"。

2026 年，AI PM 已从"新兴岗位"变为产品经理的标准形态。市场需求同比增长 178%-369%，平均月薪 19,459 元，比普通产品经理高出 20%+。

### 与传统产品经理的本质差异

| 维度 | 传统产品经理 | AI 产品经理 |
|------|------------|------------|
| **需求描述** | 功能需求文档（PRD） | 模型对话能力 + Prompt 设计 + 容错机制 |
| **输出确定性** | 确定性功能（点击→响应） | 概率性输出（同一输入可能不同结果） |
| **迭代方式** | 版本发布 | 实时数据反馈环 + 模型天级别更新 |
| **核心指标** | 留存、转化、DAU | 准确率、召回率、Token 消耗、幻觉率、任务成功率 |
| **协作对象** | 开发、设计、测试 | 算法工程师、数据工程师、MLOps、标注团队 |
| **设计哲学** | 功能完整性 | 概率化设计 + Fallback 机制 + 人机协同 |

## 二、五大核心能力支柱

### 1. 模型认知与边界管理能力（Model Literacy）

不需要写反向传播代码，但必须深刻理解大模型的能力边界。

**具体要求：**
- 知道什么任务适合用 LLM（生成、总结、推理），什么任务必须用规则引擎（精确计算、合规检查）
- 理解 Context Window（上下文窗口）限制，设计合理的记忆策略
- 理解 Temperature、Top-P 等参数对输出稳定性的影响
- 能计算 Token 成本，设计缓存策略（Cache），在效果与成本之间做 Trade-off
- 判断技术可行性：当业务方提出"用 AI 预测股票走势"时，能评估数据是否满足有效市场假说

**技术栈：**
- 大模型原理与 Transformer 架构
- 监督学习（XGBoost）、无监督学习（聚类）、强化学习的基本区别
- 模型全生命周期管理：数据采集 → 特征工程 → 模型监控（漂移检测）
- 微调技术（LoRA 适配器）、推理优化（KV 缓存配置）

### 2. Prompt 工程与结构化表达

从"自然语言"到"结构化指令"的升级。

**具体要求：**
- 设计包含角色设定、任务拆解、约束条件、Few-Shot 示例、输出 Schema（JSON/XML）的复杂 Prompt 模板
- 思维链（CoT）设计：引导模型进行分步推理，解决复杂逻辑问题
- 动态 Prompt：根据用户画像和历史行为，动态组装 Prompt 内容
- 把 Prompt 当"产品需求文档"来写

**实战案例：**
某候选人面试时拿出 Prompt 分层模板——把用户问题分成"常规咨询""复杂投诉""个性化需求"三类，针对不同类型设计了带角色设定、上下文约束的 Prompt，最终让客服应答准确率提升 28%。

### 3. Agent 与工作流编排（Agentic Workflow Design）

2026 年最热门的方向，但最容易滥用。

**具体要求：**
- **判断力**：知道什么时候该上 Agent，什么时候不该上（很多场景一个单轮生成、一个检索增强就能解决）
- 任务拆解：将模糊的用户目标拆解为多个子任务，分配给不同的 Tool 或 Sub-Agent
- 流程控制：设计 SOP 自动化执行流（如：用户说要订票→调用搜索工具→调用比价工具→调用支付工具→发送确认通知）
- 人机回环（Human-in-the-loop）：在关键决策点（转账、删除数据、医疗建议）设计人工介入机制
- 多 Agent 分工：谁负责规划，谁负责执行，谁负责检索，谁负责校验？权限如何隔离？

**核心问题：**
- 不同 Agent 之间如何传递上下文？
- 工具调用如何约束？
- 什么情况下允许自主决策，什么情况下必须人工确认？
- 不同模型如何选型和搭配？

### 4. 数据工程与 RAG 设计（Data for AI）

"语料即产品"——懂得如何清洗、标注、组织企业私有数据。

**具体要求：**
- 文档从哪里来？如何切片与检索？
- 什么时候走 RAG，什么时候直接生成？
- 如何减少幻觉？
- 如何做引用溯源？
- 用户问错时怎么兜底？
- 构建知识库 → 向量嵌入 → 相似性检索 → 增强生成

**实战指标：**
某候选人在法律文档分析工具作品集中，详细说明如何用 RAG 技术将知识召回率从 70% 提升至 92%，并附上成本测算（每千次调用成本从 0.8 元降至 0.3 元）。

### 5. 产品方案能力（容错与兜底设计）

目标不是"用了模型"，而是"交付了用户满意的结果"。

**具体要求：**
- 不仅设计理想链路，还要设计异常链路
- 不仅设计成功场景，还要设计失败场景
- 设计容错机制、兜底机制、人工介入机制和结果校验机制

**必须回答的问题：**
- 模型答不出来怎么办？
- 答偏了怎么办？
- 检索不到怎么办？
- 引用冲突怎么办？
- 生成结果不稳定怎么办？
- 执行中断怎么办？
- 工具调用失败怎么办？
- 用户不信任结果怎么办？

**典型范例：**
智能客服的"三级应答降级策略"：模型回答 → 知识库匹配 → 人工接管。

## 三、三大跨职能能力（贯穿全部支柱）

### 1. 数据驱动决策

超越表层指标，深入模型层指标。

- **传统 PM 看数据**：留存、转化、DAU
- **AI PM 看数据**：准确率、召回率、Token 消耗、幻觉率、任务成功率、一次解决率、采纳率、人工介入率
- 评测驱动开发（EDD）
- 工具：SQL、Python、AB 测试

### 2. 跨职能协作

作为"中枢角色"，协调算法、数据、MLOps等多团队。

- 技术语言沟通（能和算法工程师对话）
- 复杂依赖管理
- 风险识别与应对

### 3. AI 原生思维

不是"AI 能做什么"，而是"没有 AI，这个产品就不存在"。

- 传统思维：给客服系统加个 AI 回复功能
- AI 原生思维：设计一个 7×24 小时、零等待、千人千面的 AI 客服系统

## 五、项目经历：3 个高含金量 Side Project

以下 3 个项目来自真实转型成功案例，覆盖了 AI PM 面试最爱考察的能力点。

### 项目一：AI 简历优化 + 模拟面试助手

**适合零基础转岗者**，目标用户清晰，需求真实，容易做出 MVP。

**项目思路：**
- 上传简历后，提取经历并识别关键词缺失
- 基于目标 JD，给出简历优化建议
- 模拟面试官提问，并对回答做结构化反馈

**为什么加分：**
覆盖 AI PM 面试最爱问的几个点：
- 需求是否真实
- Prompt 与工作流怎么设计
- 输出质量怎么评估
- 用户体验如何闭环

**关键定位：** 不是单轮问答，而是**任务流产品**——涉及简历解析、岗位匹配、追问策略、反馈标准化，背后是典型的 AI 工作流设计。

**可展示成果：**
- 用户画像
- 核心流程图
- PRD 样例
- Prompt 设计逻辑
- 评估指标（命中岗位关键词比例、用户修改采纳率、模拟面试完成率）

### 项目二：企业知识库问答 Demo（RAG 思维）

适合偏 B 端、政企或 SaaS 方向。

**项目拆解：**
选一个具体行业（法务合同问答 / 医疗科普检索 / 电商客服 SOP / 公司制度问答），核心是讲清楚：
1. 文档从哪里来
2. 如何切片与检索
3. 什么时候走 RAG，什么时候直接生成
4. 如何减少幻觉
5. 如何做引用溯源
6. 用户问错时怎么兜底

**面试官最想听到：**
- 什么问题适合知识库问答，什么问题不适合
- 为什么必须有引用来源
- 如果答案错误，业务风险是什么

**核心价值：** 证明你考虑的是**业务可用性与责任边界**，而不是只关注"模型能不能回答"。

### 项目三：垂直场景 Agent 原型

证明"有想象力，也有判断力"。

**示例方向：内容运营 Agent**
输入品牌定位、目标平台、竞品链接和活动主题，系统自动输出选题建议、内容大纲、标题版本、发布时间建议，允许人工修改后继续迭代。

**关键不在多智能体有多炫，而在讲清楚：**
- Agent 的任务边界是什么
- 哪些步骤必须人工确认
- 状态怎么流转
- 出错后如何回退
- 成本如何控制

**可选垂直方向：**
- 销售线索跟进 Agent
- 教培课程顾问 Agent
- 电商运营 Agent
- 招聘筛选 Agent
- 行政流程处理 Agent

**优先做自己熟悉的方向**——转岗最聪明的方式是，把原有经验重新包装成 AI 场景优势。

### 低代码/零代码也能做的项目

用 Coze/Dify/n8n 搭建：
- 用 Coze 搭建自动产出儿童绘本视频的全流程工作流（文本脚本→自动分镜→AI 生图→视频合成）
- 搭建自动抓取 & 总结小红书热点的 Agent，每日定时推送，辅助内容选题效率提升 30%

## 六、作品集要求：闭环输出能力

AI PM 作品集不是"成品清单"，而是"思考闭环"的证明。80% 的人还在用功能 Demo 堆砌简历，真正打动面试官的是**闭环输出**能力。

### 闭环 = 黑客级输入 + 可评测输出

#### 第一部分：黑客级竞品调研报告（证明"为什么做"）

不是"我要做一个项目"，而是"我为什么做这个项目" + "我怎么判断技术水平够不够"。

**要求：**
- 像黑客一样拆解最顶尖的产品（如硅谷产品）
- 不只看 UI 交互，深入到"AI 含量"：技术选型、RAG 策略、Prompt 设计、Agent 架构
- 搞清楚赛道真实痛点是什么？竞品在"产品设计"和"技术边界"之间做了什么取舍？

**价值：** 如果你的调研报告能让面试官"从你这里学到点啥"，他就一定会认为你不错。

#### 第二部分：可量化评测体系（证明"怎么做且怎么评判"）

面试官核心问题：**"你怎么知道你做的东西'好'还是'不好'？"**

**最好的方式：讲你的"踩坑之路"**

- 我们最早选了 A 模型（坑）
- 通过评测发现它不行（证明你有落地评测能力）
- 换了 B 模型或改进了 RAG（证明你能解决不确定性）
- 最终把场景效果做到最好（证明你有把产品推高上限的能力）

**作品集必备材料：**
- PRD / 原型 / Demo
- 评测体系（怎么定义"好"的标准）
- 踩坑过程（从发现问题到解决问题的完整链路）
- 量化数据（效果提升前后对比）

### 不同背景的作品集策略

| 背景 | 策略 |
|------|------|
| **应届生** | 毕业设计结合 AI，实习项目突出 AI 落地环节（哪怕只是参与数据标注） |
| **转型者** | 将传统产品经验与 AI 结合（如"AI 驱动的个性化运营方案"） |
| **海归/外企** | 加入国产框架实践（如用飞桨 PaddlePaddle 做 Demo） |

- [ ] 用 Coze/n8n 搭建 1 个垂直场景 Agent（展示 Agent 编排能力）
- [ ] 将你的 AIGC 辅助设计经验升级为结构化 Prompt 设计案例
- [ ] 为每个项目建立评测体系（定义"好"的标准 + 踩坑过程）

### 阶段三：作品集与投递（3-4 个月）

- [ ] 完成 1 份黑客级竞品调研报告（拆解 2-3 个顶尖 AI 产品）
- [ ] 整理作品集（闭环输出：调研→设计→评测→迭代）
- [ ] 制作 AI PM 定向简历
- [ ] 从中小厂、创新业务线、传统行业 AI 岗开始投递

### 优先投递方向

| 方向 | 匹配度 | 理由 |
|------|:------:|------|
| AI + 设计工具产品 | ★★★★★ | 你的 UI/UX + AIGC 经验直接对口 |
| AI + 硬件/智能设备产品 | ★★★★ | 工业设计 + 智能中控屏经验 |
| AI + AR/空间计算产品 | ★★★★ | AR 地铁导览项目经验 |
| 通用 AI 应用产品 | ★★★ | 需要补技术基础后可投 |
