## 二、JD 五维拆解

### 1. 业务目标
为各行业客户交付**企业级软件解决方案**：从客户业务需求出发 → 定义产品功能与结构 → 输出需求文档 → 交开发落地 → 跟进整个生命周期。

### 2. 工作职责拆解（4 条）

| # | JD 原文 | 翻译成"要什么能力" |
|---|---------|------------------|
| D1 | 负责产品的详细规划和设计，包括**功能定位、产品结构设计** | 能把模糊需求拆成清晰的功能模块与结构（信息架构 / 功能架构） |
| D2 | 负责对**客户需求、市场需求和业务需求**进行调研分析，不断优化产品，提升客户体验 | 三线调研能力：客户（访谈/现场）+ 市场（行业/竞品）+ 业务（流程/数据） |
| D3 | 负责**功能需求设计，提交到开发**进行开发，**跟踪确定这一生命周期管理** | 会写需求文档 + 能盯开发进度与质量 + 有"从需求到交付"的完整跟进意识 |
| D4 | 关注**竞品动态和行业情况**，并分析总结，**将成果运用于产品中** | 竞品/行业分析能力 + 能落到产品决策（不是写报告交差） |

### 3. 职位要求拆解（5 条）

| # | JD 原文 | 拆成可验证信号 |
|---|---------|--------------|
| Q1 | 本科及以上，专业不限 | 学历门槛 |
| Q2 | 善于学习 + **归纳总结 + 数据分析**能力 | 结构化输出 + 会用数据工具 |
| Q3 | 良好**逻辑思维、沟通表达**能力 | 能理清复杂关系、能跨方对齐 |
| Q4 | **吃苦耐劳** + 渴望开阔视野 + **可以接受出差** | 愿跑现场、能扛项目节奏 |
| Q5 | **热爱互联网 IT 行业**，对产品岗感兴趣 | 有自驱的产品学习痕迹 |

### 4. 隐性要求（JD 没写但会在面试考）

- **B 端 sense**：理解"客户是企业、决策链长、需求来自业务流程"的 B 端逻辑（vs C 端用户）
- **交付意识**：项目制公司最看重"能不能按期把东西交出去"
- **文档能力**：B 端方案靠文档对齐，PRD / 方案 / 使用手册是日常
- **抗压与出勤**：出差 = 驻客户现场，节奏由项目决定

### 5. 岗位画像结论

**这是一份"B 端产品经理基础盘"JD**——考的是「调研 → 文档 → 跟进 → 竞品」四件事 + 吃苦耐劳的态度。证据链完整度决定竞争力，**态度项（出差意愿）必须明写**。

## 七、面试高频追问预备

**Q："你做过 B 端产品吗？"**
> 校园项目以 C 端为主，但融水实习天天在"商家（客户）— 平台（系统）— 履约（业务）"之间对需求，这是 B 端的微观版本；加上 5 份 PRD 的文档功底，B 端产品经理的"调研—写文档—盯落地"三件事我都干过小号版本。

**Q："能接受出差是什么理解？"**
> 去客户现场听需求、驻场陪实施——这正是我想要的：开阔视野、见真实业务。融水实习就是在县域市场跑出来的，我不怕跑。

**Q："你一个工业设计的为什么做产品？"**
> 设计科班训练的就是"用户调研 → 需求定义 → 方案落地"这条链，只是交付物从造型换成了产品方案；而且我比多数 PM 候选人多一手"画得出来"（Figma / XMind 原型与流程图）。

**Q："怎么把竞品分析用到产品里？"**
> 举宠芯例子：竞品功能矩阵 + 问卷数据 → 砍掉低优先级功能、聚焦核心场景——"分析总结并运用于产品"我做过完整闭环。
