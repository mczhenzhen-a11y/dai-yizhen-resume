## 四、版本 Q 定制策略

### 叙事主线切换
- **设计岗简历**（A~P 版）：我是"能落地方案的设计师"
- **本版（PM 岗）**：我是"**做过完整产品思维训练、带过团队、交付过真实商业订单的设计背景候选人**"

### 五个关键改写动作
1. **标题定位改为"产品设计 → 产品经理方向"**，突出可迁移性而非设计专业深度
2. **核心能力区重写为 PM 框架**：需求洞察与分析、产品规划（服务蓝图/商业模式画布）、跨团队推动落地、数据驱动决策、学习迭代能力
3. **融水实习经历升级**：从"实践经历配角"提升为 PM 叙事核心证据（跨部门协调 + 198,000 元订单 + 13% 收益率，是唯一带真实商业数字的落地案例），措辞从"协助"调整为如实但更主动的"跟进/整合/推动"
4. **项目排序按 PM 含金量**：亲子系统（leader + 服务架构 + 商业画布）→ AR 地铁导览（leader + 需求拆解 + 功能优先级）→ 宠芯（数据驱动需求验证）→ 智能中控屏（产品定义）
5. **自我评价按"沟通/团队/学习"三条 JD 软素质 + 产品潜力"写**，并保留电商业务兴趣表达（公司为电子商务行业）

### 关键词融入对照
JD 原词 → 版本 Q 中的自然出现位置：
- "产品全生命周期" → 核心能力 + 亲子/AR 项目描述
- "协调跨部门资源推动项目落地" → 核心能力 + 融水实习
- "收集并分析用户需求" → 核心能力 + 宠芯/握力圈
- "持续优化" → 各项目迭代描述
- "学习能力" → 自我评价 + AI 知识体系自主调研

### 合规边界
- 不虚构 PRD 文档、竞品分析报告、Axure 使用经验
- PM 方法论表述以真实使用过的工具为准：服务蓝图、商业模式画布、用户画像、问卷、用户流程图
- 融水实习保持"协助/跟进"真实性，仅强化责任动词，不夸大职权
